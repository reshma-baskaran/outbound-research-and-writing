# Contributing

Contributions that improve research discipline, sequence quality or workflow
safety are welcome.

1. Open an issue describing the problem and expected outcome.
2. Keep account claims source-backed and keep hypotheses out of recipient copy.
3. Do not add recipient data, credentials, private campaign copy or fictional
   customer outcomes.
4. Add or update tests for behavior changes.
5. Run `python -m unittest discover -s tests -v` before opening a pull request.

Sequence changes must preserve the fail-closed input gate, six distinct touch
roles, `Hi [first name],` greeting and sender-derived signoff.
